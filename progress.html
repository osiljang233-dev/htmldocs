# KBO·MLB 픽 파일 구조 확인 — 조회만 (수정 금지)

앞서 KBO 픽이 파일명(`picks_날짜.json`) 때문에 임포터에서 스킵된 거 확인했어. 이번엔 그 파일 내용이랑 MLB도 같은지만 봐줘. **코드 건드리지 마. 조회만.**

1. **`picks_2026-08-22.json`·`picks_2026-08-23.json`(KBO 오후 zip 안) 안에 뭐가 들었어?**
   - KBO 픽만이야, 아니면 MLB·다른 리그도 섞인 통합 파일이야?
   - 각각 몇 건이고 리그 구성이 어떻게 돼?

2. **MLB 픽은 어떤 파일명으로 와?**
   - 8/20 아침 zip엔 `picks_mlb_ko_*.json` 이 있었어? (그날 MLB 픽은 들어갔음)
   - 8/21·8/23 zip엔 MLB 픽 파일이 있었어? 있었으면 파일명이 정확히 뭐야?
   - MLB 픽 파일명이 날마다 달라, 아니면 고정이야?

3. **dailypick 임포터가 픽 파일을 찾을 때 쓰는 glob 패턴 전체를 알려줘.**
   `import-snapshot-flex.php` · `import-picks-dailypick.php` 둘 다에서, 어떤 파일명들을 기대하는지 그대로.

# KBO 당일픽 상태 확인 — 조회만 (수정 금지)

**코드 건드리지 마. 상태만 알려줘.**

서버에 8/22·8/23·8/24 KBO 당일픽이 0건이야. 그날 배치 반입할 때 KBO 픽이 어떻게 처리됐는지만 확인해줘.

1. **8/22·8/23 KBO 오후 배치 zip 안에 KBO 픽 파일이 있었어?**
   있으면 파일명을 그대로 알려줘 (예: `..._KBO_picks_....json` 형태인지, 아니면 다른 이름인지).

   - `skipped` 였는지
   - 넣었으면 몇 건인지
   - `reason` 이 뭐라고 찍혔는지

3. **`scripts/import-picks-dailypick.php` 가 KBO 픽에 대해 실제로 실행됐어, 아니면 스킵됐어?**
   스킵됐으면 왜 스킵됐는지 (파일명 패턴 `*_KBO_picks*.json` 에 안 걸려서인지, decision 이 전부 null 이라서인지).
