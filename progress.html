# 픽 임포터 수정 — picks_날짜.json 도 받게 (백업 먼저, 안전장치 있음)

## 배경 (짧게)
머니라인 픽이 `picks_YYYY-MM-DD.json` 으로 오는데, dailypick 트리거가 `*_KBO_picks*.json`·`picks_mlb_ko_*.json` 만 찾아서 매일 스킵돼. 그래서 KBO·MLB 머니라인 픽이 안 들어와. (결과·순위·축구 픽은 멀쩡히 들어오고 있음)

## 1. 먼저 백업
`scripts/import-snapshot-flex.php` 를 `scripts/import-snapshot-flex.php.bak-0824` 로 복사.

## 2. 확인 먼저 — 고치기 전에 이것부터 봐줘 (중요)
`scripts/import-picks-dailypick.php` 가 `picks_YYYY-MM-DD.json`(머니라인 픽) 을 읽어서 실제로 픽을 넣을 수 있는 구조인지 먼저 확인해줘.
- **읽을 수 있으면** → 3번으로 진행
- **못 읽으면(형식이 다르면)** → ★ 고치지 말고 멈춰. `picks_2026-08-22.json` 안 첫 20줄이랑, import-picks-dailypick.php 가 기대하는 형식이 어떻게 다른지 보고만 해줘. (그때 우리가 다시 지시할게)

## 3. 트리거 glob 에 패턴 추가
`scripts/import-snapshot-flex.php` 에서 dailypick 트리거가 픽 파일을 찾는 glob (`*_KBO_picks*.json` / `picks_mlb_ko_*.json` 잡는 곳, 578행 근처).

- **기존 두 패턴은 그대로 두고**, `picks_YYYY-MM-DD.json` 형식(예: `picks_[0-9][0-9][0-9][0-9]-*.json`)을 잡는 패턴 **하나만 추가**.
- "현재 줄 / 변경 줄" 전문을 그대로 적어서 보고.

## 4. 절대 건드리지 마
결과(`*_results_ko_*.json`)·순위(`*_standings_*.json`)·축구 픽(`{리그}_picks`) 임포트 경로. 지금 잘 들어오고 있어. 여기는 손대지 마.

## 5. 반영 후 재import
8/22·8/23·8/24 KBO·MLB 배치를 재import 해서, 그날 픽이 실제로 들어갔는지 확인.

# 오늘의PICK 중복 카드 제거 (좁은 판) + 종료 경기 상태 오판정 수정

작성일: 2026-08-24
대상 서버: News.php (application/controllers/News.php)
base 118,533바이트 (DevFS 실측 · 로컬 사본과 바이트 수 일치 확인함)
**이 파일 안의 2건만 하고 멈춰줘. 순서대로 1건 끝내고 2건으로 넘어가.**

---

## 왜 하는 작업인지

`/news/category/dailypick` 에 브라질레이랑·MLS 경기가 카드 두 장으로 겹쳐 나와.
하나는 news 글(`/news/view/829` 같은 주소), 하나는 피드 카드(`/news/soccer/{리그}/picks` 로 감).
같은 경기가 피드에도 있으면 news 글 쪽은 빼줘.

**단, 피드에 짝이 없는 축구 news 글은 그대로 둬.** 세리에A·라리가·프리메이라·리그1·MLS 일부는
피드에 지금 자료가 없어서 news 글이 유일한 화면이야. 그것까지 지우면 그 경기가 화면에서 통째로 사라져.
그래서 "축구 리그면 무조건 뺀다"가 아니라 "같은 경기가 피드에도 있으면만 뺀다"로 짜줘.

두 번째는 별개 버그. 오늘의PICK 요약 줄에 "진행 중 22 · 예정 0" 처럼 뜨는데,
경기가 시작만 하면 몇 시간 지나도 계속 "진행 중"으로 잡혀서 그래. 종목별 소요 시간을 더해서
그 시간이 지나면 "진행 중"에서 빼는 걸로 고친다.

화면에 영향 있는 수정이야. 카드 개수가 줄고 진행 중/예정 숫자가 바뀔 거야.

---

## 0. 백업

```bash
cp application/controllers/News.php application/controllers/News.php.bak-20260824-dailypick
```

```php
                $days[$day][] = $row;
            }
        }
        krsort($days);
        $pick_days = [];
        foreach ($days as $d => $rows) {
            $pick_days[] = (object)['d' => $d, 'cnt' => count($rows)];
        }
        if ($undated) {
            $pick_days[] = (object)['d' => 'undated', 'cnt' => count($undated)];
        }
        return ['days' => $days, 'undated' => $undated, 'pick_days' => $pick_days];
    }
```

### 4. 주의할 점

- `$feed_rows = $this->dailypick_soccer_rows();` 를 맨 위에서 **한 번만** 불러서 두 군데(열쇠 만들 때·아래 두 번째 foreach)서 재사용해. 예전 코드처럼 두 번 부르지 마.
- MLB·K리그1 news 글은 `meta['home']`/`meta['away']` 값이 있어도 **피드 열쇠에 원래 안 걸려**. 피드(`dailypick_soccer_rows`)는 `self::$soccer_leagues` 만 돌기 때문에 야구·K리그1은 애초에 `$feed_keys` 에 안 들어가. 그래서 이 코드는 MLB·K리그1을 건드리지 않아. 리그 이름으로 따로 걸러낼 필요 없어.
- `sort($pair)` 는 배열을 팀 이름 알파벳/가나다 순으로 정렬해서 "팔메이라스 vs 바스코" 와 "바스코 @ 팔메이라스" 처럼 순서가 달라도 같은 열쇠가 되게 하는 거야. 빼먹으면 매칭이 하나도 안 걸려.
- 두 번째 `foreach ($feed_rows as $row)` — 여기는 원래 `$this->dailypick_soccer_rows()` 를 다시 부르던 자리야. `$feed_rows` 로만 바꾸는 거고 안의 로직은 그대로 둬.
- 들여쓰기는 스페이스 8칸(메서드 안 기준)·12칸(foreach 안) 그대로 맞춰줘.
