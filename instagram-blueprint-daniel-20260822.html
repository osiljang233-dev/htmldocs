인스타 · SEO·웹 · 픽랩2 — 앞으로 이렇게 가자는 판이에요
2026-08-21 보고
알고리즘 리서치(PRD)를 «할 일» 로 바꿔놨어요. 소재는 논쟁·비교, 저장은 랭킹, 첫 2주는 릴스예요.
데이터·제작 게시·운영 나중에·조건부

큰 결정 3개

① «분석» 말고 «논쟁·비교» 를 팔아요
비팔로워한테 뻗는 제일 센 신호가 DM 공유(친구한테 보냄)예요. 좋아요의 3~5배거든요. 근데 「EPL 시즌 분석」 을 친구한테 보내는 사람은 없죠. 「손흥민 vs 박지성 누가 위냐」 는 보내요.
그래서 매일 팀vs팀 · 선수vs선수 카드 1건 을 축으로 가요. 데이터는 그 싸움을 «끝내는 증거» 로 깔아요.
② 저장을 노려요 — 랭킹 · Top5 · 티어표
저장이 좋아요보다 훨씬 세게 쳐줘요. 그리고 저장을 제일 잘 만드는 게 «나중에 또 볼» 랭킹·리스트예요.
리그별 랭킹·Top5 데이터를 계속 공급해요. 「KBO 타격 Top5」 「유럽파 폼 티어표」 이런 거요.
③ 첫 2주는 릴스로 문을 열어요
새 계정은 팔로워 관계 점수가 0 이라 카드뉴스가 뻗을 데가 없어요. 릴스만 «오디션» 으로 비팔로워한테 나가거든요.
그래서 첫 2주는 릴스 비중을 올려요. 경기 끝나면 미친 기록 하나 를 바로 뽑아요.

실제로 이렇게 생겨요 — 예시 3개

카드뉴스 8장 — 「손흥민 vs 박지성, EPL 전성기」
1장질문 훅 + 큰 숫자 하나 2장★ 반전 수치 (2장부터 보는 사람 잡는 훅) 3~7장항목별 1:1 비교 (경기당 공격포인트 · 빅매치 · 수상…) 장당 하나씩 8장저장·공유 유도 + 다음 편 예고
인스타가 스와이프 안 한 팔로워한테는 «2장부터» 다시 보여주거든요. 그래서 2장도 훅이어야 해요.
릴스 7~15초 — 「KBO 타격 Top5, 5위부터 소름」
0~3초 「5위가 얘라고?」 → 카운트다운 5→1 → 1위에서 반전. 자막은 꼭 넣어요 (무음으로 보는 사람이 많아요). 첫 3초에 못 잡으면 안 퍼져요. 그래서 훅 문구 후보를 데이터랑 같이 준비해요.
스토리 매일 — 투표 「오늘 한화 vs LG 누가 이길까요?」
다음날 결과 + 데이터 카드로 회수해요. 투표·답장이 관계 점수를 쌓아서 피드 도달이 올라가요.

만드는 방식 — Lovart 로 한 번에

① 데이터·훅 문구·캡션 키워드 뽑기→ ② Lovart — 카드 8장 / 릴스 초안 «한 번에» 생성→ ③ 사람 검수 — 숫자·금지선 확인→ ④ 게시 + 60분 댓글 대응
Lovart 하나로 카드 + 릴스 둘 다 뽑아요
AI 디자인 에이전트라 브랜드 템플릿(색·폰트·로고) 한 번 잡아두면 카드 세트를 일괄로 뽑아줘요. 비디오도 돼요 — 비디오 모델 15종(Sora 2·Runway 등)·최대 10분·4K. 그래서 릴스도 여기서 나와요. 하루 3~4회 게시를 사람 손으로 다 그리면 못 버티는데, 이 방식이면 데이터 → 완성 카드·영상까지 흐름이 짧아져요.
스포츠 데이터 릴스는 실사 영상이 아니라 랭킹 카운트다운·수치 모션 그래픽 이라 도구 하나로 충분해요. 먼저 시험 1회 — 카드 시안 1편 + 짧은 릴스 하나 뽑아보고 품질·속도·비용을 봐요.
AI 로 만들어도 괜찮은가 — 괜찮아요, 조건이 있어요
PRD 확인 — AI 생성물 자체는 금지가 아니에요. 「사람이 만든 원본」 우선이라, 직접 만든 데이터 카드는 원본으로 쳐줘요. 대신 똑같은 레이아웃을 반복하면 자동화로 의심받아 배포가 깎여요.
템플릿을 2~3벌 만들어 돌려 쓰고, 훅·색·구성을 매번 조금씩 바꿔요. 남의 이미지·중계 클립은 아예 안 써요 (저작권).

PRD 가 이러니까 → 이렇게

PRD 내용그래서 이렇게
첫 30~60분 반응이 확산을 결정해요 게시 시간대(가설: 출근·점심·저녁 21~23·경기 직후)에 맞춰 데이터를 미리 준비해 둬요. 훅 문구 후보도 같이요
주제가 흐린 계정은 추천에서 빠져요 · 캡션은 검색어처럼 Ahrefs 키워드로 캡션 검색문장을 대줘요 — 웹이랑 같은 키워드로 묶어요 (「손흥민 2026 시즌 기록」 식)
남의 이미지·중계클립 재가공은 위험해요 (원본성·저작권) 시각화를 직접 만든 데이터로만 해요. 클립을 아예 안 쓰니 저작권이 안 걸려요
같은 캡션·구조 반복하면 자동화 의심으로 배포가 깎여요 같은 소재라도 수치·훅·비교 대상을 매번 바꿔서 뽑아요
검증 항목 — 한국 스포츠 데이터 상위 계정 분석 벤치 요청 항목을 페이블5 연구로 넘겨요. 남들이 뭘로 먹히는지 보는 게 제일 빠른 답이에요

2주 시험 — 지어내지 말고 데이터로 알아내요

뭘 해요뭘 봐요
1단계 · 2주4소재(논쟁 · 반전수치 · 랭킹 · 한방) 각각 릴스 2~3개. 바이오에 「스포츠 데이터/기록」 박고 시작해요 저장률 2%+ · DM공유율 1%+ · 비팔로워 도달 50%+ (PRD 초안 기준)
2단계반응 온 소재 1~2개로 좁혀서 반복하고, 카드뉴스 비중을 올려요캡션·훅은 매번 바꿔요
금지선 (YMYL) — 적중률·수익률·보장·확실 숫자는 안 내보내요. 팀의 실제 기록(홈 승률 같은 것)은 괜찮아요. 내보내기 전에 한 번 걸러요. 웹에서 지켜온 규칙 그대로예요.

바로 굴릴 수 있는 것

  • 바로 카드 시안 1편 — 소재 하나 골라 실데이터로 8장 만들어 봐요 (Lovart 시험을 여기 겸해요)
  • 바로 벤치 요청 항목 정리 → 페이블5 연구로 (장수·게시시간·캡션·훅 패턴)
  • 대기 소스 자료 오면 카드용 가공 시작해요
  • 대기 피그마 지침서 담당자 전달 — 디자인 3개 확정(페이지명·접근·S7노드) 오면 넘겨요
꾸준히 해나가야 하는 것들이에요 — 한 방이 아니라 계속 쌓아야 유입이 늘어요. 전부 «이미 있는 데이터» 재활용이에요.

해야 할 일 7개

1. 선수 이름을 받는 페이지가 없어요 새 페이지
GSC 보면 검색 의도가 「순위·로스터」 인데, 정작 «선수 이름» 으로 들어올 문이 없어요. 「손흥민 다음 경기」 「김민재 팀 순위」 칠 사람은 많고, 답(소속팀 순위·일정·폼)은 이미 갖고 있거든요.
유럽파 3~5명(손흥민·이강인·김민재…)부터 허브 페이지 하나씩. 있는 데이터를 선수 축으로 다시 묶기만 하면 돼요.
2. 「경기 몇시」 검색은 답이 «한국시간» 하나예요 롱테일
「토트넘 경기 몇시」 — 유럽 경기는 시차 변환이 답의 전부잖아요. 일정 데이터에 KST가 이미 있어요.
일정 탭 title·description 에 「한국시간」 을 박아요. 「이번 주말 EPL 몇시」 류 FAQ도 일정에서 자동으로 뽑혀요.
3. 상대전적 vs 페이지 새 페이지
「토트넘 아스날 상대전적」 — 검색 패턴이 굳어 있는 말이에요. 빅매치 주간마다 검색이 몰려요.
먼저 맞대결 데이터가 있는지 세보고요, 있으면 빅매치 주간에만 vs 페이지를 만들어도 유입이 와요.
4. 구조화 데이터 — 브레드크럼 다음 수 신호 보강
지금 브레드크럼 JSON-LD 넣는 중이잖아요. 그 다음은 SportsEvent(일정)랑 FAQPage(핸디캡 규칙 설명이 이미 글로 있어요).
일정이 리치결과로 뜨면 같은 순위여도 클릭을 더 가져가요. 있는 화면에 마크업만 얹는 일이에요.
5. 시즌 전환 키워드 선점 지금이 때예요
8월 = 검색이 「2026-27」 로 갈아타는 달이거든요. 작년 시즌 표기로 남아 있으면 새 시즌 검색을 통째로 놓쳐요.
title·h1·description 시즌 표기를 전수 점검해요. 「2026-27 EPL 순위」 로 미리 서 있는 쪽이 가져가요.
6. 출처 페이지 — YMYL 신뢰 보강 신호 보강
베팅 인접 주제라 구글이 신뢰를 깐깐하게 봐요. 근데 「이 데이터 어디서 오나」 를 밝히는 장이 없어요.
출처·갱신 주기 한 장 + 각 표에 갱신 시각 표시. 금지 표현 0건으로 지켜온 게 자산인데 보여줄 데가 없었잖아요.
7. 내부링크 그물 — 링크는 공짜예요 신호 보강
픽 글 → 그 리그 순위표 → 그 리그 픽 탭이 서로 안 이어진 데가 있어요. 구글은 링크 없는 페이지를 늦게, 얕게 봐요.
고아 페이지부터 세보고, 픽↔순위↔일정을 서로 이어요. 코드 몇 줄로 사이트 전체가 촘촘해져요.

Ahrefs — 위 아이디어를 «검증하는 도구» 로 써요

결제해놨으니 안 쓰면 돈만 나가요
첫 걸음은 크레딧 잔량 파악이에요 — 그래야 뭘 아껴서 뽑을지 정해지거든요.
쓰는 순서: ① 위 아이디어 검색어 실측(진짜 치는 말인가·경쟁은 어떤가) → ② 키워드 갭(못 받고 있는 검색어) → ③ 경쟁사 백링크. 여기서 나온 키워드가 웹 문구랑 인스타 캡션에 똑같이 들어가요 — 한 번 뽑으면 두 채널이 같이 써요.

THE STATLAB — 추후 고려

버저비터에서 «픽을 뺀» 순수 데이터 사이트 — 광고 태울 자리예요 나중에
본체는 픽(베팅 인접) 때문에 광고를 못 붙이잖아요. 픽 뺀 순위·일정·기록 사이트면 광고가 붙어요. 버저비터 복사 → 이름 「THE STATLAB」 → 픽 제거 → 새 도메인. 1차는 NBA 오프시즌. 지금은 아이디어만 잡아두고, 여유 생기면 착수해요.
★ 메인 테스크가 아니에요. 세션 하나 새로 파서 «돌려놓고», 결과만 보는 사이드 실험이에요.

뭘 해보는 거냐면

지금까지 쌓인 MLB 경기를 뒤져서, 어떤 지표가 승패를 갈랐는지 «추적» 하는 게 핵심이에요
선발 ERA · 타선 · 불펜 · 최근 폼 … 이 중에 뭐가 이길 팀을 실제로 맞혔나 를 끝난 경기들로 역추적해요. 기여도가 큰 지표를 골라내는 게 1순위고, 그걸 조합해서 공식을 만드는 건 그다음 이에요.
공식이 나오면 끝난 경기로 백테스트해서 공식 vs 기존 픽 vs 배당 — 셋 중 뭐가 나은지 숫자로 봐요. 기존 픽(hit)이 벤치마크고요.

왜 해볼 만하냐 — 공짜거든요

있는 것picks.jsonl 535픽 · 픽마다 gamePk(MLB 공식 게임 ID) · 정답(hit)까지 다 있어요
없는 것경기 «전» 지표 — 근데 gamePk 를 StatsAPI(공짜·공개)에 넣으면 전부 역으로 끌려와요
빼는 것「사후 발행」 픽 — 경기 끝나고 쓴 건 예측이 아니니까 평가에서 빼요
표본도 돼요 — 팀당 약 125경기(학습) + 시즌 끝까지 약 5주(안 본 경기로 검증).

어떻게 굴리냐 — 이 세션은 안 써요

  • ① 30분 정찰 — 있는 535픽으로 «지표랑 승패가 상관이 있긴 한가» 만 먼저 봐요. 신호 없으면 여기서 접어요
  • ② 신호 있으면 — 새 워크스페이스 C:\bb-picklab2-workspace 에 세션을 파서 «돌려놔요»
  • ③ 끝난 MLB 경기 지표를 전부 모아 지표별 기여도 추적 — 어떤 게 승패를 잘 갈랐나 순위를 매겨요
  • ④ 기여 큰 지표를 조합해 공식 → 안 본 경기로 백테스트 → 기존 픽·배당과 비교
  • ⑤ 계산은 로컬 파이썬이 해요 (토큰 거의 0). 가끔 결과만 들여다봐요

결과는 이렇게 다뤄요

내부에서만 확인하고, 적중률이 높게 나오면 그때 공유해요
먼저 내부에서만 돌려서 공식이 진짜 쓸 만한지 봐요. 검증도 안 된 걸 밖에 내보내면 오히려 신뢰가 깎이니까요. «충분히 높게» 나온 다음에야 공유를 얘기해요. 그 전엔 내부에서만.

선 세 개

발행 안 해요 — 적중률 숫자가 화면에 나가면 정책 위반(YMYL)이에요. 어디까지나 내부용이에요.
과최적화 조심 — 학습에 쓴 경기로 채점하면 다 맞는 것처럼 보여요. 학습/검증 경기를 갈라놔요.
