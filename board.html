# News.php — board 날것 주소 2개를 정식 페이지로 301

## 0. 백업

작업 전에 백업부터 만들어줘.

```
cp application/controllers/News.php application/controllers/bak-board301-News.php
```

## 1. 대상

- 파일: `application/controllers/News.php`
- base 크기: **122,039 바이트** (오늘 KBO 라벨 반영본)
- 위치: `board()` 메서드 안 `$bb_board_redir` 배열 끝 (1991~1992행 부근)

## 2. 무슨 작업인지 (한 줄)

`/news/board/mlb_review` · `/news/board/kbo_review` 두 날것 주소를 각자 정식 리뷰 페이지로 301 리다이렉트한다. (배열에 2줄만 추가)

## 3. 바꿀 것 — "현재 / 변경" 전문

배열 끝 `'wnba_lineup'` 줄 바로 아래, 닫는 `];` 위에 2줄을 넣는다.

### 현재 (그대로 있어야 함)

```php
            'wnba_lineup'    => 'news/basketball/wnba/lineup',
        ];
```

### 변경 (2줄 추가)

```php
            'wnba_lineup'    => 'news/basketball/wnba/lineup',
            'mlb_review'     => 'news/baseball/mlb/review',
            'kbo_review'     => 'news/baseball/kbo/review',
        ];
```

## 4. 건드리면 안 되는 것

- `$bb_board_redir` 배열의 **다른 줄 전부** — 값 하나 바꾸지 마
- 1322행 KBO 탭 라벨(`'파워랭킹 / 로스터'`) — 그대로 둔다
- `board()` 의 다른 분기(soccer redir·noindex·전용 뷰), 다른 메서드 전부 무변경
- 배열 키·따옴표·화살표 정렬 그대로. **줄 2개만 추가한다. 삭제 없음**

## 5. 왜 이렇게

- 두 날것 주소가 정식 페이지(`/news/baseball/mlb/review`·`/news/baseball/kbo/review`)와
  같은 제목·같은 데이터인데 각자 자기 자신을 canonical 로 가리켜 **중복 색인**되고 있었다.
- 이미 kbo_roster·축구 21종·순위표들 40여 개를 같은 방식(301)으로 처리해둔 목록이다. 그 밑에 2줄만 얹는다.

## 6. 수정 후 보고할 것

- 수정한 파일·줄 번호·**실제로 들어간 코드 2줄**
- 수정 후 News.php **바이트 수** (2줄 늘어야 정상)
- `php -l application/controllers/News.php` 문법 통과 여부

★ check.py 는 돌리지 마. 검증은 이쪽에서 실서버로 한다.
