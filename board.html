# 92단계 — 글 제목에 경기 날짜 붙이기

파일 하나다. `application/controllers/News.php`

```
base   85,938 바이트 · 1,551줄        ← 시작 전에 이 값이 맞는지 봐줘. 다르면 멈추고 알려줘
```

---

## 1. 백업 먼저

```bash
cp /var/www/sportsnews/application/controllers/News.php \
   /var/www/sportsnews/application/controllers/bak5-News.php
```

## 2. 왜 고치나

`/news/view/{id}` 130건 중 **85건의 `<title>` 이 글자까지 같다.** 37묶음이야.

```
/news/view/700 · 719 · 735 · 743
  전부   보스턴 레드삭스 @ 토론토 블루제이스 — 보스턴 레드삭스 승 · 스포츠뉴스
```

같은 두 팀이 며칠 뒤 다시 붙으면 제목이 그대로 재사용돼. 제목에 날짜가 없어서야.

경기 날짜는 **이미 DB 에 있다.** `meta` 컬럼 안의 `start_at` 이고,
`application/views/front/view.php` 39행·80행이 이미 그 값으로 「경기 2026.08.10 08:10」 을 찍고 있어.
**같은 값을 제목에도 쓰는 것뿐이야. 새 자료는 필요 없어.**

## 3. 무엇을 고치나

`News::view()` 안이다. **505행은 그대로 두고, 506행 `];` 다음에 새 줄을 넣는다.**

### 현재 (504~508행)

```php
            'comment_count' => $this->cmm->count_for('news', $id),
            'title'      => $item->title . ' · 스포츠뉴스',
        ];

        // tg78085 — article meta description from body lead (first ~150 chars)
```

### 변경 후

```php
            'comment_count' => $this->cmm->count_for('news', $id),
            'title'      => $item->title . ' · 스포츠뉴스',
        ];

        /* tg-step92: 제목에 «경기 날짜» 를 붙인다.  같은 대진이 며칠 뒤 다시 붙으면
           title 이 글자까지 같아져서, 색인된 글 130건 중 85건이 중복이었다.
           값은 meta.start_at 이고 view.php 39·80행이 이미 같은 값을 쓴다 — 화면과 안 어긋난다.
           start_at 이 없는 글은 이 if 가 안 걸려서 옛 제목 그대로다. */
        $__m92 = json_decode((string)($item->meta ?? ''), true);
        $__ts92 = (is_array($__m92) && !empty($__m92['start_at'])) ? strtotime($__m92['start_at']) : false;
        if ($__ts92) {
            $data['title'] = $item->title . ' (' . date('Y.m.d', $__ts92) . ') · 스포츠뉴스';
        }

        // tg78085 — article meta description from body lead (first ~150 chars)
```

**넣는 것은 위의 9줄(주석 4줄 + 코드 5줄)뿐이다.** 지우는 줄은 없다.

## 4. 건드리지 마

```
is_indexable · robots  526행 아래.  손대지 마
```

`<h1>` 도 이번엔 안 바꾼다. 본문에 이미 경기 날짜가 찍혀 있어서 h1 에 또 넣으면 겹쳐.

# 91단계 — 픽 글에 「경기 시각」을 찍는다

작성 2026-08-16 · 대상 서버 = 버저비터.com (`/var/www/sportsnews`)
**이 1건만 하고 멈춰줘.** 90단계까지 다른 코드는 건드리지 말아줘.

---

## 왜 하는 작업인지

픽 글 화면에 **발행일만 있고 「언제 경기인지」가 없어.**

```
지금     2026.08.16 12:00 · 조회 43
바뀔 것   2026.08.16 12:00 · 경기 2026.08.16 03:20 · 조회 43
```

★ **자료는 이미 서버에 있어.** `meta.start_at` 이고, 오늘의PICK 이 그걸로 날짜를 묶어.
39행에서 `$__start_ts` 로 이미 만들어 놨고, 61~67행이 **시각(`H:i`)만** 찍고 있어. 날짜가 없어.

★ **왜 날짜가 필요한가.** 사람이 「이게 오늘 경기야 어제 경기야」를 못 가려.
MLB 는 같은 대진이 사흘 연속 붙어서 `03:20` 만 봐서는 어느 날인지 모르거든.

```
파일 1개 · 1곳   application/views/front/view.php
현재 크기        13,517바이트 · 271행
화면 변화        ★ 발행일 줄에 「· 경기 …」 한 조각이 붙는다.  나머지는 그대로
삭제             없다
사이트맵          194건 그대로.  색인 신호는 안 건드린다
```

---

## 0. 백업

```bash
cp application/views/front/view.php application/views/front/view.php.bak91-20260816
```

- [끝] 발행 배관 고침 (bbstat_publish TARGETS) — 픽랩 «빈 틀» 을 올리게 돼 있었다. 루프가 재시작되면 라이브가 통째로 날아간다. 이름이 한 글자 차이라 눈으로는 안 걸리고 크기(242KB vs 486KB)로만 걸린다
- [끝] 점수 정렬 버그 · 빈 칸 정렬 — 점수 꼴이 「2-1」 로 바뀌면서 -1 을 음수로 읽어 득점차가 3이 됐다. 「7 : 5」 로만 시험하면 안 잡힌다. 그리고 「—」 246개가 오름차순에서 맨 위를 덮고 있었다
- [끝] 보고 배선 잇기 (wrap_{슬러그}.json) — 코드는 daily/{날짜}-{부서}.md 를 찾는데 세션 합의는 wrap_design.json 으로 바뀌어 있었다. 둘 다 없어서 보고가 영원히 뼈대만 나왔다
- [봐야 함] 유럽 5대 리그 자료 07-30 정지 — 복구 zip 이 들어왔는데 안 살아났다. 두 세션이 따로 재서 같은 결과다. 「자료가 안 온다」 가 아니라 「와도 들어갈 자리가 없다」. 08-22 개막부터 순위표가 0-0-0 으로 나간다
- [폐기] border-image 로 만든 손그림 테두리 — 파도는 없앴는데 그냥 반듯한 둥근 사각형이 됐다. 사용자가 「너무 반듯하다」 고 해서 버리고 feTurbulence 로 갔다
- [폐기] 채점 0인 리그줄을 «흐리게» — 흐려도 아무 말 안 하는 줄이 11개 남는 건 같았다. 숨기는 쪽으로 바꿨다
- [폐기] 「채점 안 함」 라벨 — «영영 안 한다» 로 읽힌다. 실제로는 아직 안 열린 경기였고, 몇 시간 뒤 채점이 켜졌다. 「리그 픽」 으로 바꿔 둬서 안 낡았다
- [폐기] 리그 칩 배지를 MLB 만 붙이는 안 — 「리그끼리 견줄 수 있어야 한다」 가 A 를 고른 이유인데 배지가 하나면 견줄 게 없다. 값만 보고 «보여줄지 말지» 정하는 조건문을 안 봤다
