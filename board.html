# 117단계 — 야구 픽 카드 확률 막대 채우기 (2차, 컨트롤러)

★ 이건 디자인 1차 뷰 배포(빈 필드 숨김·무승부 2칸) «뒤에» 보낸다. 순서 지켜.

파일 하나: `application/controllers/News.php`
- base **110,233바이트** · md5 **84ec2581172a37cbdbfc8994624e8874**
- 고칠 함수 `render_baseball_picks()` = **1316행부터**

## 0. 백업
작업 전 `News.php` 를 `bak7-News.php` 로 복사.

## 1. 무슨 건
야구 픽 카드의 홈/원정 확률 막대(sb-wdl)가 지금 0%로 비어 있어. 야구 글엔 확률 필드가 없고
요약(summary)에 "홈 승률 67%" 문자열로만 있거든. 그걸 뽑아서 막대에 넣어줘.
막대는 값×100 을 width 로 쓰니까 0~1 소수로 넣는다 (홈 67% → 0.67).

## 2. 현재 함수 (전문)

```php
    private function render_baseball_picks($league, $meta) {
        $picks = $this->soccer_picks_merged([], $league);
        $data = [
            'soccer_league' => $league,
            'soccer_tab'    => 'picks',
            'soccer_meta'   => $meta,
            'page'          => 'baseball_' . $league,
            'active_cat'    => 'baseball_' . $league,
            'board_kind'    => $league . '_picks',
            'board_label'   => $meta['label'] . ' 픽',
            'payload'       => $picks ? ['picks' => $picks] : null,
            'dates'         => [],
            'cur_date'      => $this->pick_today_kst(),
            'title'         => $meta['label'] . ' 픽 · 스포츠 뉴스',
        ];
        $settings = $this->stm->all();
        $settings['seo_description'] = $meta['label'] . ' 픽 — 앞으로 열릴 경기의 픽을 가까운 순서로 모았습니다. 근거와 확인율을 함께 봅니다.';
        $data['settings'] = $settings;
        if (!$picks) $data['robots_override'] = 'noindex, follow';
        $this->layout('front/soccer_board', $data);
    }
```

## 3. 바꿀 함수 (전문)

`$picks = $this->soccer_picks_merged([], $league);` 바로 «아래»에 확률 주입 루프만 넣어줘.
나머지는 그대로.

```php
    private function render_baseball_picks($league, $meta) {
        $picks = $this->soccer_picks_merged([], $league);
        /* tg-step117: 야구 픽엔 engine.probabilities 가 없다. summary "홈 승률 N%" 로 홈/원정 막대를 채운다 */
        foreach ($picks as $__i => $__p) {
            if (preg_match('/홈\s*승률\s*([0-9]+(?:\.[0-9]+)?)\s*%/u', (string) ($__p['summary'] ?? ''), $__mm)) {
                $__hw = (float) $__mm[1];
                if ($__hw >= 0 && $__hw <= 100) {
                    $__e = (isset($__p['engine']) && is_array($__p['engine'])) ? $__p['engine'] : [];
                    $__e['probabilities'] = ['home' => $__hw / 100, 'away' => (100 - $__hw) / 100];
                    $picks[$__i]['engine'] = $__e;
                }
            }
        }
        $data = [
            'soccer_league' => $league,
            'soccer_tab'    => 'picks',
            'soccer_meta'   => $meta,
            'page'          => 'baseball_' . $league,
            'active_cat'    => 'baseball_' . $league,
            'board_kind'    => $league . '_picks',
            'board_label'   => $meta['label'] . ' 픽',
            'payload'       => $picks ? ['picks' => $picks] : null,
            'dates'         => [],
            'cur_date'      => $this->pick_today_kst(),
            'title'         => $meta['label'] . ' 픽 · 스포츠 뉴스',
        ];
        $settings = $this->stm->all();
        $settings['seo_description'] = $meta['label'] . ' 픽 — 앞으로 열릴 경기의 픽을 가까운 순서로 모았습니다. 근거와 확인율을 함께 봅니다.';
        $data['settings'] = $settings;
        if (!$picks) $data['robots_override'] = 'noindex, follow';
        $this->layout('front/soccer_board', $data);
    }
```

# 107단계 — 삭제한 85건을 **되돌려줘**

사용자 결정이다. 06:00 정기 덤프에 있다고 네가 확인해줬다.

---

## 1. 무엇을

```
2026-08-17 07:16 에 hard DELETE 한 news 행 85건 (dailypick · 165 → 80)
→ 08-17 06:00 KST 정기 덤프에서 «그 85건만» 되살린다
```

★ **덤프 전체를 되돌리지 마라.** 그 뒤에 들어온 새 픽(791~804)과 다른 작업이 날아간다.
**지운 85건만** 골라 넣는다.

---

## 2. ★ 왜 되돌리나 — 판정 기준이 너무 넓었다

네 보고에 이렇게 적혀 있었다.

```
「source 가 mlb_AWAY_HOME_해시 면 해시를 뺀 mlb_AWAY_HOME 키.
  키마다 가장 큰 id 만 남기고 나머지 hard DELETE.
  ★ 날짜가 다른 경기·본문이 달라도 같은 팀 대진이면 한 그룹」
```

**그게 문제다.** 같은 두 팀은 시즌에 여러 번 만난다.

```
8월 7일  보스턴 @ 피츠버그    ← 다른 경기
8월 17일 보스턴 @ 피츠버그    ← 다른 경기
★ 대진 키가 같다는 이유로 «한 그룹» 이 됐고 하나만 남았다
```

**중복은 「같은 날 같은 대진」 이다. 날짜가 다르면 다른 경기다.**
우리가 사이트맵 전수로 센 진짜 중복은 24건(12쌍)이었다. 85건이 지워졌다.

---

## 3. 되돌린 뒤 — 중복은 «좁은 기준» 으로 다시 정리해줘

되살리면 진짜 중복 12쌍이 같이 살아난다. 그건 다시 정리해야 한다.

```
★ 중복 기준을 이렇게 바꿔줘
  같은 «경기일(meta.start_at 의 KST 날짜)» + 같은 대진   → 중복
  날짜가 다르면                                      → ★ 중복이 아니다
```

그 기준으로 남길 것을 고를 때도 **가장 큰 id** 가 아니라 **내용이 더 채워진 쪽**이면 좋겠다.
판단이 어려우면 가장 큰 id 로 해도 된다 — 다만 «같은 날» 안에서만이다.

---

## 4. 순서

```
1  85건 복구
2  복구 뒤 건수 보고         (dailypick published 가 165 근처로 돌아와야 한다)
3  좁힌 기준으로 중복 재정리   → 24건 안팎이 지워질 것이다
4  최종 건수 보고
```

★ **3번을 하기 전에 2번 숫자를 먼저 알려줘.** 우리가 대조하고 3번 진행 여부를 말하겠다.

---

## 5. 끝나면 이걸 보고해줘

```
1  복구한 건수와 «id 목록» (85개)
2  복구 뒤 dailypick published 건수
3  /news/view/720 · 769 · 782 · 765 · 779 · 767 · 756 의 HTTP 상태  (전부 200 이어야 한다)
4  /news/category/dailypick/2026-08-17 · 2026-08-18 의 고유 글 수
5  사이트맵 <loc> 총건수와 /news/view/ 건수
```

★ 3번(중복 재정리)은 **이 보고를 받고 우리가 「진행해」 라고 한 뒤에** 해줘.

---
